# 舞台の図書室の検索・読み取りの復旧

## 原因

名前選択への変更後、サーバーのデータ取得は公開用Supabaseクライアント（`anon`）になりましたが、公演アーカイブのテーブル・ビュー・RPCは従来の `authenticated` にのみ読み取り権限がありました。

本番DBへの読み取りで、`archive_actor_options` / `archive_staff_options` / `archive_role_options` と `archive_work_stats` に対する `42501: permission denied` を確認しました。これをコードが空配列に変えていたため、読み込み失敗と「検索結果なし」を区別できませんでした。

## 必要なDB作業

同じディレクトリの `archive-name-selection-read.sql` を対象プロジェクトの **Supabase → SQL Editor** で実行します。

- 公演アーカイブの5テーブル・5ビュー・10関数に限り、`anon` のSELECT / EXECUTEと読み取り用RLSポリシーを付与します。
- 名前選択は本人認証ではないため、公演アーカイブ自体の読み取りは公開用APIからも可能になります。アプリ画面の名前選択は引き続き必要です。
- INSERT / UPDATE / DELETE権限を追加しません。RLSを無効化しません。
- `profiles`、個人の観劇記録、Supabase Auth、`shiki_works` / `shiki_theaters` は対象外です。
- SQLはトランザクション内で実行され、再実行も可能です。

作業環境にDB管理接続がないため、作成時点でこのSQLは**未実行**です。コードのデプロイだけではDB権限は変わりません。

## コードの修正

- すべての図書室クエリがDBエラーを呼び出し元へ伝えます。権限エラーを0件や404にしません。
- 検索は読み込み失敗と0件を区別し、失敗時は再試行できます。旧名・全半角・英字大小・かな・名前内の空白にも対応します。
- 作品・出演者・役・スタッフ・劇場を選ぶ検索と、装丁風の作品の本棚を用意します。作品一覧は表にも切り替えられます。
- 日付ページの前日・翌日へ移動した際、日付入力も移動先に合わせて更新します。

## 確認

`npm run test:archive` で検索の表記揺れ、旧名からの移動先、24個のクエリにおけるエラー伝播を確認できます。

DB適用後は入口の5種類の検索から各詳細ページを開き、作品・役・出演者・スタッフ・劇場の関連リンクと日付検索を確認します。未適用時は読み込み失敗として表示されます。
