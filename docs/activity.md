# 行動記録

`/activity`。映画・ファンミーティング・コンサート・観劇・その他を、実際に行った記録として残す。既存の `/theater-log` はキャストや俳優別の振り返り用として維持し、別テーブルで保存する。予定や行動記録を観劇実績の集計へ勝手に混ぜない。

## 入力と表示

種類・日付・作品／イベント名・会場を必須にし、時刻・都市／エリア・短いメモは任意。キャスト・写真・評価は不要。時刻を入力しなかった場合はNULLを保持し、0時を補わず「時刻未記入」と表示する。過去の記録も登録できる。未来の日付は私の予定へ案内する。日付と時刻は日本時間。

新しい日付から月別に並べ、年・種類・作品／会場／都市／メモの検索で絞れる。全体の記録数と会場名の種類数も表示する。会場名数は名称の文字列による集計で、地理的な会場同定済みの施設数ではない。

「私の予定」の過去・当日の公演は利用者が「行った」と確認してから登録。非公演項目・落選・キャンセル・未来の予定は引き継がない。種類・日時・作品名・会場をフォームへコピーし、確かめて保存する。元の予定のメモは自動転記しない。Googleの同期だけで行動記録を作らない。

`source_plan_id` で同じ予定からの二重登録を防ぐ。登録後はスナップショットとして独立し、元予定の更新・削除から実際の記録は書き換わらない。元の予定が削除されても記録本体は残り、参照だけNULLになる。手入力は別の鑑賞回を同名で複数残せる。

## 利用者と保存

各ページで `requireJournalMember`、全APIで現在の選択名を確認。既存の個人・知人用の名前選択方式を継続し、本人認証と呼ばない。GET/PATCH/DELETEはサーバーでuser_idを絞る。POSTのuser_id/idは受け付けずサーバーから指定する。引き継ぎ元の予定も同じ利用者のものか確認する。更新時に参照先の予定IDは書き換えない。変更系APIは同一Originを必須とし、一覧と詳細はprivate/no-store。

`activity_records` はRLS有効で、anon/authenticatedへの権限・公開Policyなし。既存のサーバーservice_roleにSELECT/INSERT/UPDATE/DELETEのみを付与。新規作成と同じmigration内で既定ACLを取り除く。既存表のACLは変更しない。UUIDなのでシーケンス権限は不要。owner+dateと参照元の予定IDを索引化。

Supabase管理連携で `20261027065532_activity_records` を適用した。同一SQLをリポジトリへ保存。CLIは以前に設定ディレクトリの書き込み不可で起動できなかったため、管理連携が発行した番号を使用。既存の記録・予定のデータは操作せず、検証用データはPGliteとブラウザフィクスチャのみで扱う。全体baselineの未完成は変わらず、db resetや新規環境全体の動作を確認したものではない。

## 今後の地図・移動アニメーション

今回は未実装。会場名と都市から候補を検索し、利用者が位置を確認できる仕組みを後で追加する。名称だけから緯度経度を推測して保存したり、都市の中心を実際の会場として扱ったりしない。

位置が確定した会場を日時順に線で結ぶ再生は可能。実際の交通経路やGPS移動履歴とは区別する。時刻不明の同日記録は訪問順が分からないため、順序の確認や不明表示が必要。今回の画面には地図や再生ボタンを設置せず、追加予定の説明だけを表示する。

## 検証

`npm run test:activity` は入力・未来日・不明時刻、種類・年・検索、所有者の偽装拒否・他の利用者の予定や記録へのアクセス拒否、CSRF、編集・削除を検証。PGliteで旧来の自動GRANTあり／なしの双方からDDLを実行し、ACLとRLS、CRUD、元予定との独立、削除時の参照解除、二重登録の拒否を確認。

`npm run test:supabase` にも追加し、SQL登録一覧を更新。ブラウザは実コンポーネント＋APIフィクスチャで4幅、5種類、入力・編集・削除、検索・年絞り込み・予定引き継ぎ・エラー再試行を確認する。本番への個人データのテスト投入はしない。

本番のRLS・公開ロールのSELECT拒否・service_roleのCRUD権限と空の記録表を確認済み。Supabaseアドバイザーの[RLS Enabled No Policy](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)はINFO表示になるが、サーバー経由のみの設計として意図した状態。公開Policyを追加しない。

## 思い出の日本地図（2026-10-27）

`/activity/map`。行動記録の上部「思い出の日本地図」および下部の案内から開く。名前選択後の本人用画面。記録1件＝1回として、同じ正規化済み会場名＋エリアに積み上げる。NFKC・小文字化・空白除去のみで、部分一致や都市中心への自動配置はしない。エリア表記が違う同一会場は別扱いなので、記録の会場名とエリアを揃える。

- 年・種類を絞り込み。再生は日付単位、同日の記録はまとめて追加。未知の時刻を補わず、訪問順・実際の移動経路を捏造しない。再生は手動開始、一時停止、速度、スライダー、全件表示に対応。
- 近い会場を集約。画面の幅とズーム倍率を考慮し、集約マーカーはクリックで拡大。ズーム・ドラッグ・方向ボタン・日本全体に戻るボタン。会場コレクションからも単独会場を選択できる。
- マーカーを押すと会場別の記録と編集リンク。回数は常に正確。塔は最大高さと描画段数を調整し、大量記録でも描画を抑える。色は記録の種類。reduced-motion時は段追加の動きを止める。
- 日本全体の概略図はNatural Earthの50m Admin 0 Countries、日本の外周（小数4桁）を同梱。小さい島を省略する概略図。出典： https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_50m_admin_0_countries.geojson 。Public Domain： https://www.naturalearthdata.com/about/terms-of-use/ 。海外の会場表示は対象外。2026-10-28にLeafletによる詳細地図も追加（下記）。

### 会場の位置

`lib/activity-map.ts`に大阪四季劇場と舞浜アンフィシアターの会場位置を登録。会場名の完全一致＋対応するエリアだけに適用する。アクセス案内： https://www.herbis.jp/shop/detail/97 、https://www.maihama-amphitheater.jp/access/ 。大阪の座標参照： https://commons.wikimedia.org/wiki/Category:Osaka_Shiki_Theatre 、舞浜の座標参照： https://www.event-tenki.com/maihama-chiba8/ 。施設の概略位置であり座席や入口の位置を表すものではない。

未知の会場は位置未設定として一覧に残し、地図の表示件数と全記録数を分けて表示する。会場コレクションの位置設定から、Googleマップを別タブで検索し、利用者が確認した緯度・経度を入力して保存。公開の地理検索サービスへ行動記録を自動送信しない。自分で保存した位置を優先し、解除すると既知会場の標準位置に戻る。同じ会場名＋エリアの将来の記録にも反映。削除した行動記録が塔の回数に残ることはない。

位置は`activity_places`に個人別で保存。既存の行動記録や予定の行・ACLは変更しない。RLS有効、anon/authenticated/Publicは無権限、service_roleだけSELECT/INSERT/UPDATE/DELETE。今の名前選択方式を引き継ぎ、厳格な本人認証を追加したものではない。APIは全操作で選択名のIDを使用。保存時は該当する自分の行動記録があることも確認する。緯度20～46、経度122～154の表示範囲と有限数の検証を行うが、日本の行政区域内かの判定を行うものではない。

`migrations/20261027093002_activity_places.sql`はSupabase管理連携で適用済み。CLIが読み取り専用ホームへの作成で失敗する環境のため、破棄可能なPGliteでSQLを検証後、apply_migrationで本番へ適用し、サーバー発行の番号で同じSQLを保存した。既存の完全baseline不足・db reset未検証の制限は変わらない。

## 地域の拡大・会場別の塔（2026-10-28）

日本全体の概略図を残し、Leaflet 1.9.4の詳細地図を追加。東京・舞浜、竹芝、横浜、名古屋、大阪・京都のショートカット、および訪問先全体を収める操作を用意。詳細地図はネイティブの＋−、ホイール、ダブルクリック、ピンチ、ドラッグ、キーボードで操作できる。会場コレクションの「地図で見る」も詳細地図を開く。

- 遠くからはエリア別の回数と会場数を表示。まとまりを押すと必ず会場を個別表示する倍率へ進む。詳細表示は会場ごとに独立した塔と会場名を表示する。
- 春・秋・自由劇場などの近接会場は画面上で塔とラベルを離して配置し、実際の会場位置を点＋点線で結ぶ。会場の保存座標は変えない。同じ建物にある別会場も一つの塔に合算しない。
- 高さは絞り込み対象全体の最大訪問数から固定の段高を計算し、地域・ズーム・再生位置が変わっても維持する。近い場所をまとめた概略表示の塔だけは上限高さで縮尺調整する。詳細地図では各会場の回数がそれぞれの高さになる。
- 再生も会場別の詳細地図を使用し、移動と背景画像の準備完了を待つ（手動開始、下記の表示待ち対策）。同日の複数会場はまとめて写し、未確認の訪問順は作らない。「再生中は地域をなめらかに追う」を外すと手動で見ている範囲を保持。地域・会場の拡大ボタンからも任意の場所を開ける。reduced-motion時はカメラを即時切り替え、到着の動きも行わない。
- Leafletはクライアントのeffect内で動的ロードし、SSRでwindowへ触れない。アンマウントで地図・ResizeObserverを破棄する。

街路・地名の背景は利用者のブラウザから`https://tile.openstreetmap.org/{z}/{x}/{y}.png`へ直接リクエストする。ブラウザ既定のキャッシュ・Refererを保持し、表示領域外の一括取得や先読み機能は設けない。OpenStreetMapの帰属表示を地図内に常時表示。代替のOSM由来サービスへ切り替える場合は`NEXT_PUBLIC_MEMORY_MAP_TILES`を指定し、そのサービスの規約と帰属条件も別途確認する。APIキー・有料契約は追加していないが、OSM標準タイルはベストエフォートの外部サービス。読込に失敗した場合は案内を出し、会場マーカーと日本全体の概略図に戻る操作を残す。

参照： [Leaflet公式API](https://leafletjs.com/reference.html)、[OpenStreetMap標準タイルの利用方針](https://operations.osmfoundation.org/policies/tiles/)。利用者が保存した位置を読み取り、個人の行動記録・位置・スキーマ・既存権限は変更しない。

追加のモデルテストでは、地域の選択、会場別の高さ、同一座標にある3会場のラベル分離、元データの非変更と配置の再現性を確認。ブラウザfixtureでは詳細地図のエンジン・マーカー・操作を実際に実行し、背景タイルだけ人工画像に置換（外部画像の本番配信確認とは別）。1440/768/390/320pxで3劇場の分離と高さ比較、キーボード、ズームボタン・ホイール、再生カメラ追従と停止、reduced-motion、タイル障害時の案内を確認する。

## 全国から目的地へ寄るズーム再生（2026-10-28）

サンプルで確認した演出を行動記録へ統合。列車シーンを廃止し、`ZoomMemoryMap`で「全国1.4秒 → 目的地へズーム3秒 → 塔の積み上げ1.1秒 → 滞在 → 全国へ引く2.7秒」を日付ごとに繰り返す。再生完了後も全国と累積した塔を残す。初期表示も道路・地名のある全国地図。地域ボタン・会場の詳細ボタンから手動で拡大できる。

- `lib/activity-zoom.ts`は固定した画面上の点を軸にスケールを補間。カメラ中心と倍率を独立に補間せず、拡大してから横移動する動きや、横移動してから引く動きを防ぐ。戻りは同じ軌道の逆再生。
- 再生にもOpenStreetMapの道路・地名タイルを表示する。会場とタイルは同じWeb Mercator座標で配置する。現在の表示範囲だけを取得し、読み込み済みの粗い地図を下層に保持して、細かい画像が届いてから上に重ねる。保持は最大160タイル。初期地図と到着時の読み込みを待ち、失敗時は案内と再試行を表示する。手動表示はLeafletと既存の読み込みゲートを維持。
- 作品名・会場名・日付・エリアはサンプルと同じ地図内の右下カードに表示。初期表示でも再生の最初の目的地を案内する。スマートフォンでもカードを地図内の下側に重ね、地図の下へ移動させない。同日複数会場は全会場が収まるカメラと案内を使い、訪問順を捏造しない。
- 記録は到着のフェーズから塔に加算する。近接会場は寄ると塔を分け、線で実座標を示す。段の高さは全記録から求めた共通基準。表示は最大60色帯、回数は正確に維持する。
- 一時停止は同じフェーズから再開。日付スライダーの操作時はその日までの累積を全国で表示。フィルター・全表示は再生を解除する。速度は滞在時間を変更し、カメラのズーム時間は変えない。
- 「目的地へズームする」を外すと全国に固定。動きを減らす設定ではカメラ移動を省略し、短いフェーズで記録をたどる。
- 利用者の行動記録・位置情報・DB・APIは変更しない。

検証：固定点と往復のカメラ軌道のモデルテスト、実コンポーネントのブラウザ検証（複数地域・近接会場・同日複数会場・右下カード内の作品名・回数・停止再開・スライダー・年と種類・スマートフォン・街路詳細への切替）。ブラウザfixtureの背景画像は検証用の人工画像で、実際の地図配信とは区別する。
