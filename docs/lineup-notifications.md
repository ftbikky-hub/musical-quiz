# Gmailで公式ラインアップの変更を知らせる

設定画面: `/lineup/notifications`。上演予定ページ下部の「公式の変更をGmailで受け取る設定」から開けます。

## 初回設定（利用者のGoogleアカウントで行う）

1. 設定画面の「Apps Scriptを開く」で新規プロジェクトを作成する。通知を受け取るGmailのGoogleアカウントを使う。
2. 「通知用コードをコピー」で `public/downloads/lineup-monitor.gs` の内容をコピーし、初期コードをすべて置き換えて保存する。
3. 関数欄で `setupLineupNotifications` を選び「実行」。Googleの権限確認で内容を確認して許可する。許可後に処理が終わっていない場合はもう一度実行する。
4. 自分宛ての「上演予定お知らせの送信テスト」と、Apps Scriptの実行ログの「設定完了」の**両方**を確認する。テストメールだけでは定期実行が有効になったと判断しない。

Googleのメール送信・外部ページ取得・実行者のメールアドレス取得・定期トリガー管理を使います。Gmail受信箱の読み取り、Drive、Resend、独自ドメイン、APIキーは使いません。Googleの利用枠を超えると処理を失敗扱いにし、自動で有料プランに切り替えません。

このチャットのGmail接続からApps Scriptの作成・権限許可・定期実行登録はできません。そのため、初回設定は本人による操作が必要です。まだGoogle上での初回実行・公式からの実取得・実メール送信・トリガー登録は未実施です。設定画面だけでは利用者の稼働状況を判定できません。

## 動作

- 毎日9〜10時頃（Asia/Tokyo）。Googleの時間指定は正確な9時を保証しません。
- 初回の公式情報を比較基準に保存します。既存サイトの2026-10-21スナップショットとの内容比較や、過去の変更通知はしません。
- 毎回HTMLから予定表画像を発見し、画像バイトのSHA-256を比較。URLの`ver`値だけ変わっても同一内容なら通知しません。
- ラインアップ本文の「※」で始まる注記も正規化して比較。関係のないフッターやナビの変更を通知しません。
- 変更した地域の表と、追加・削除・変更された注記を**プレーンテキスト**でメール送信します。画像の具体的な公演・日付は読み取りません。
- 公式の3地域の表や注記が確認できない場合、取得失敗として扱い、前回の比較基準を保持します。HTTPエラー・画像不正・大幅な形式変更も同様です。
- 同じ取得エラーの通知は、復旧するまで一度だけ。変更なしの日にはメールしません。
- 変更通知の送信が失敗した場合は比較基準を進めず、次回に再試行します。
- 正常な通知後は基準を進めるので、同じ状態を繰り返し通知しません。ただしメール送信直後から状態保存までの間に実行が異常終了した場合など、メールと保存の間の原子的な一回保証はありません。
- 比較基準とチェック日時はUserPropertiesに、トリガーはそのGoogle利用者のプロジェクト内に保存。同時実行はUserLockで抑制します。
- スクリプトを共有して使い回すより、各利用者が自分の非公開プロジェクトへコピーする運用を想定します。

## 変更しないもの

サイトの公演JSON・未発表日付・お気に入り・DBには書き込みません。OCR / AI / 自動反映・更新承認画面は今回の対象外です。メールにも「サイトの公演データはまだ更新していません」と明記します。

## 手動確認・停止・再開

Apps Scriptで関数を選んで実行：

| 関数 | 操作 |
| --- | --- |
| `checkLineupNotifications` | 有効な通知設定で今すぐ比較。変更がなければ送信しない |
| `showLineupNotificationStatus` | 有効/停止、最終試行・成功・変更通知日時、最終エラーを実行ログへ表示 |
| `stopLineupNotifications` | この通知だけを停止。比較基準は残す |
| `setupLineupNotifications` | 設定・再開。再実行でもこの通知のトリガーが重複しない。他のトリガーは消さない |

実行者メールを取得できない場合、個人のGoogleアカウントで実行しているか確認します。組織管理アカウントでは管理者の制限が適用される場合があります。HTTPエラーや構成変更は実行ログを確認します。自作プロジェクトのGoogle確認画面で止まる場合は、表示内容を確認してから対応してください。

## 検証と限界

```sh
npm run test:lineup-notifications
```

同じ `.gs` ファイルをNodeのVMで実行し、Googleサービスのモックで初回・再実行・内容ハッシュ・注記差分・失敗時の基準保持・送信失敗の再試行・停止/再開・形式不正・ロックを確認します。実メールは送りません。公式HTMLの構造を模したfixtureでの検証であり、Googleから公式を取得する実機検証の代わりにはなりません。

設定画面は4画面幅・コピー成功・クリップボード拒否時のコード欄・ダウンロードをローカルブラウザで確認しています。

参考：[MailApp](https://developers.google.com/apps-script/reference/mail/mail-app)、[時間トリガー](https://developers.google.com/apps-script/guides/triggers/installable)、[利用制限](https://developers.google.com/apps-script/guides/services/quotas)。
