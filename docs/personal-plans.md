# 私の予定

`/plans`。観劇・コンサート・抽選締め切り・当落発表を、日付順の手帳として表示する。月間カレンダーは使用しない。近い公演と締め切り／発表を上段に置き、種類・検索・これから／過去と終了で絞り込む。

## 利用者と公開範囲

ページは `requireJournalMember`、全APIは `getCurrentJournalMember` で選択名を確認。未選択はページでログインへ、APIでは401。名前選択Cookieは本人認証ではなく、既存の個人・知人用の方式を継続している。登録名を選べる人がその名の予定を利用できるため、「本人だけに秘密」の権限とは呼ばない。

`personal_plans` は既存の観劇記録と違い公開Data APIのSELECTを付与しない。全操作をサーバーのservice_role経由とし、GET/PATCH/DELETEのクエリは必ず選択名のuser_idで絞る。POSTは入力のuser_id/idを受け付けずサーバーで所有者を指定。JSONの許可フィールドを正規化し、日付・時刻・URL・長さ・状態を検証。更新系は同一Originを必須とする。取得はprivate/no-storeで、1000件ずつ最後まで読む。GoogleのOAuthトークンやカレンダー共有URLは保存しない。

## 保存用SQL（本番実行は未実施）

既存スキーマは変更せず、既知の `auth.users(id)` に関連する追加テーブルのみを作る。

- migration: `supabase/migrations/20261022000000_personal_plans.sql`
- SQL Editor用の同一内容: `/downloads/personal-plans-setup.sql`
- Supabase SQL Editorで上記SQLを一度実行する。テーブル未作成時は画面に初回設定の案内を表示する。
- 新規作成時にRLSを有効にし、既定ACLを取り除きservice_roleにSELECT/INSERT/UPDATE/DELETEのみ明示。anon/authenticated/PUBLICへの権限・Policyは作らない。既存表があればACLを書き換えない。UUID採番なのでシーケンス権限は不要。
- `SUPABASE_SERVICE_ROLE_KEY` は既存のサーバー用設定を利用。ブラウザには渡さない。

作業環境にはDB管理接続もサービス用キーもなく、実DBへのテーブル作成・本番の保存確認は未実施。既存アプリの管理用キーを用いるVercel上で、SQL実行後に確認する必要がある。リポジトリ全体のbaselineは未完成で、この追加migrationだけで全DBをresetできるとは扱わない。

## 公演と抽選

公演日・時刻（時刻は任意）、会場、状態、URL、メモを保存。観劇・コンサートには締め切りと当落発表の日付・任意の時刻を関連づけられ、一つの公演から最大3件の日付を一覧へ展開する。落選・キャンセル・完了は「過去・終了」へ。時刻未登録を0時や終日確定に変換しない。日付単位で当日の予定を残し、日本時間の翌日から過去に分ける。

作品の選択は既存 `archive_works` のIDで `/archive/works/:id` へつながる。上演予定の詳細から作品・劇場名を引き継いで予定を作成できる。未発表の日付は引き継がず手入力で確定する。観劇記録は観た後に別途登録し、予定を実績として自動集計しない。

## Googleカレンダー

中心はGoogleからのファイル取り込み。PC版Googleカレンダーの設定→インポート／エクスポート→エクスポートで取得したZIPを利用者が展開し、`.ics`を選ぶ。

- `ical.js` でブラウザ内解析し、当日以降の候補を表示。候補全体はサーバーへ送らない。観劇などのキーワード一致を初期選択し、種類を修正・チェックして選んだ最大100件だけ保存。候補の分類はキーワードによる補助で確定判断ではない。
- ファイル上限2MB、VEVENT上限2,000件。繰り返しとその例外、キャンセル済み、確認できない日時、重複UIDなどは件数とともに除外を案内する。出席者・メールアドレスは予定フィールドに取り込まない。
- JST、UTC、ファイル内VTIMEZONEを扱う。浮動時刻はX-WR-TIMEZONE（指定がなければAsia/Tokyo）を使用し、未解決のタイムゾーンは推測せず除外する。終日の排他的DTENDは最終日のinclusive値へ変換する。
- 元UIDを `source_uid` に保存し、(user_id,source_uid) の一意制約とignoreDuplicatesで再取り込みをスキップする。保存後の編集内容を上書きしない。Google側での変更・削除は自動反映されず、登録済み予定をこのページで編集する。
- 各項目にはGoogleカレンダーの追加画面へのリンクと`.ics`出力もある。追加リンクは利用者がGoogle側で保存するまで書き込まない。出力は日本語・改行のエスケープとUTF-8の75オクテット折返しに対応。未登録の終了時刻は作らない。

OAuthによる継続的な自動同期は未実装。ChatGPTのGoogle連携の権限をサイトが継承することはない。予定・締め切り・発表のメール通知も未実装で、上演予定の公式変更通知とは別機能。

## 検証

`npm run test:plans`：入力、日付順と抽選日付、日本時間、ICSのJST/UTC/終日、繰り返し等の除外、出力、未選択401、他の名の予定への404、所有者の偽装不可、Origin検証。

`npm run test:supabase`：追加migrationを実際のPostgreSQL（PGlite）で実行し、自動GRANTの有無両方で公開アクセス拒否・service_roleのCRUD・RLS・既存ACL維持を検証。

ブラウザは実コンポーネント＋APIフィクスチャで4幅の表示、入力・編集、絞り込み、選択取り込み・重複、設定未完了の案内と再試行を検証。本番DBに利用者の代わりのテスト予定は作成しない。
